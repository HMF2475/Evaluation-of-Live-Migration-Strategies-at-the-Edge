# WebAssembly migration

This module benchmarks live migration for a WebAssembly application made by [Edoardo Tinto](https://github.com/TintoEdoardo).

## Current scope

1. Reproduce Edoardo Tinto's proof-of-concept.
2. Run the same checkpoint/restore flow between `edge-node-1` and `edge-node-2`.
3. Collect the same CSV-style timing metrics used by the CRIU experiments.
4. Repeat the edge-node run from `run_all.py`.

Start with `simplest-example/README.md`. It runs the existing injected WASM files from
`wasm-migrate-commands/wasm_test_computation/`.

## Edge-node setup

Install runtime dependencies in the Multipass nodes:

```bash
bash WASM-migration/scripts/setup/install_wasm_node_deps.sh edge-node-1 edge-node-2 edge-host-1
```

`--build-tools` also installs compilers, CMake, Rust/Cargo, and libcurl headers if
you want to build inside a node. The benchmark path normally transfers host-built
`create_command`, `start_command`, and `migrate_command` binaries to the nodes.

## Run one edge migration

Host mode copies the checkpoint archive from source to destination through the
host machine by default. If `--relay-node` is set, it stages through that Multipass VM
instead, matching the other benchmark suites' intermediate-hop mode.

```bash
python3 WASM-migration/scripts/orchestrators/wasm_benchmark.py \
  --source edge-node-1 \
  --dest edge-node-2 \
  --transfer-mode host \
  --relay-node edge-host-1 \
  --profile-name smoke
```

Direct VM-to-VM transfer:

Direct mode sets up SSH trust automatically, then copies the checkpoint archive
from source VM to destination VM with `scp`.

```bash
python3 WASM-migration/scripts/orchestrators/wasm_benchmark.py \
  --source edge-node-1 \
  --dest edge-node-2 \
  --transfer-mode direct
```

For a quick smoke test, use one run of each mode:

```bash
python3 WASM-migration/scripts/orchestrators/repeat_wasm_benchmarks.py suite \
  --strategies cold \
  --source edge-node-1 \
  --dest edge-node-2 \
  --relay-node edge-host-1 \
  --host-runs 1 \
  --direct-runs 1 \
  --profile-name smoke
```

## Repeat benchmark

```bash
python3 WASM-migration/scripts/orchestrators/repeat_wasm_benchmarks.py suite \
  --strategies cold \
  --source edge-node-1 \
  --dest edge-node-2 \
  --relay-node edge-host-1 \
  --host-runs 20 \
  --direct-runs 20 \
  --snapshot-node-metrics \
  --profile-name "PROFILE"
```

`benchmarks.json` includes this command, so `run_all.py` runs it under each network profile.

Plots are generated by default into `WASM-migration/metrics/plots/<batch>/`. Use
`--no-plots` only when you want to collect CSV/logs without rendering figures.

## Metrics capture points

- `checkpoint_ms`, `checkpoint_us`, `checkpoint_ns`: source-side injected log delta from `request_server - checkpoint start` to `request_server - checkpoint completed`.
- `archive_create_ms`: source-side Python timer around copying `main_memory.b` and `checkpoint_memory.b` into the state directory and creating `wasm-state.tar.gz`.
- `archive_bytes`: size of `wasm-state.tar.gz`.
- `transfer_setup_ms`: transfer-path setup, including IP lookup, source-file checks, SSH trust setup, and SSH connectivity tests.
- `transfer_send_ms`: first archive copy. Direct mode uses this for source VM to destination VM; host/relay mode uses it for source VM to relay/host stage.
- `transfer_receive_ms`: second archive copy for host/relay mode, from relay/host stage to destination VM. It is normally zero in direct mode.
- `transfer_cleanup_ms`: removal of temporary relay/host-stage files.
- `transfer_ms`: raw Python wall-clock around the transfer helper, including setup, copy leg(s), and cleanup.
- `unpack_ms`: destination seeding time. It extracts the archive and places memory files where the destination runtime expects them.
- `restore_ms`: broad destination timer. It starts before destination server launch, includes `unpack_ms`, sends `start_command`, and ends when the destination log emits `request_server - restore memory completed`.
- `downtime_ms`: raw CSV value `checkpoint_ms + transfer_ms + restore_ms`, matching the CRIU CSV schema.
- Plotted downtime/transfer values: generated plots subtract `transfer_setup_ms` and add `archive_create_ms`. They do not add `unpack_ms`, because `unpack_ms` is already included in the current broad `restore_ms`.
- Process metrics: `create_command` prints `server_pid=<pid>`; the Python wrapper
  snapshots `/proc/<pid>` via the Linux proc API before/after key phases.
- Node metrics: optional node_exporter before/after snapshots are summarized into `metrics/node_exporter_metrics.csv`.
- Plots: `downtime_comparison.png`, `phase_breakdown.png`, `transfer_analysis.png`, `transfer_phase_breakdown.png`,
  and, when node snapshots exist, `node_exporter_summary.png`.
